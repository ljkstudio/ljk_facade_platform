# 복곡면 블랭크 전개 — 설계

- 날짜: 2026-08-14
- 패키지: `unfold/` (저장소 `26_AdaptiveMold_development` 안, `adaptive_mold/`와 형제)
- 브랜치: `feature/unfold-v1`
- GH 컴포넌트: `UFv1 Flatten`, `UFv1 Material`

---

## 1. 무엇을 만드는가

복곡면 패널을 **성형 전 블랭크(재단 도형)** 로 펴는 Grasshopper 컴포넌트.

곡면 한 장을 받아 평면 메쉬로 펴고, 요소별 변형률을 계산하고, 재단할 외곽 곡선을
여유를 포함해 돌려준다.

### 무엇이 아닌가

- 종이 전개가 아니다. 복곡면은 원리상 정확히 펴지지 않으므로 **면적이 보존되지 않는다.**
- 정밀 블랭크 역산이 아니다. 성형 후 트림이 허용되는 공정이라 **경계가 공차 안에 들
  필요가 없다.** 필요한 보증은 하나 — 과소재단이 아닐 것.
- 네스팅·여러 장 동시 처리·절곡 플랜지·소성 모델·스프링백은 v1 범위 밖이다(§12).

## 2. 배경 — 기각한 대안

### 2.1 상용 API 구매 (ExactFlat)

`dev/AI-unfolding-app` 이 2026-01 에 택했던 길. **ExactFlat SDK 를 받지 못해 7개월 정지.**
남은 산출물은 조사 문서와 OCCT 프로토타입뿐이고, 전개 알고리즘은 한 줄도 우리 것이 없다.

기각 사유: 트림이 허용되므로 상용 엔진이 주는 정밀도가 필요 없다. 대금·라이선스·응답
대기가 전부 순비용이다.

**뒤집을 조건**: 트림 없는 공정(재단선이 곧 제품 외곽)으로 바뀌면 다시 검토한다.

### 2.2 곡률선 스트립 분할 후 정확 전개

주곡률 방향 좁은 띠로 잘라 각 띠를 원뿔 근사로 정확히 편다. `dev/DEVELOPABLE-SURFACE`
의 곡률선 코드를 재활용할 수 있었다.

기각 사유: 결과가 **여러 조각**이다. "한 장을 재단한다"는 목적과 어긋난다.

**뒤집을 조건**: 패널이 한 장으로 성형 불가할 만큼 깊어지면(연신 한계 초과) 분할이
필요해진다. 그때는 패널 분할 프로젝트에서 다룬다.

### 2.3 LSCM 초기값

ARAP 의 초기 배치로 널리 쓰이는 등각 매개화.

기각 사유: 별도의 복소 최소자승 조립이 필요한데, **Tutte 매립은 이미 만들 라플라시안
솔버를 그대로 쓴다.** 파일 하나와 코드 한 벌이 줄어든다. ARAP 은 초기 배치가 뒤집히지만
않으면 되고 등각성은 반복이 지운다.

### 2.4 one-step inverse 소성 FEM (v1 에서)

판금 블랭크 역산의 산업 표준(Autoform One-step 계열).

기각 사유 둘:

1. **검증 불가.** 실물도 계측도 없다. 맞는지 알 방법이 없는 코드가 된다.
2. **블랭크를 별로 안 바꾼다.** 얕은 외장 패널의 주변형률은 몇 % 수준이라 1500mm 패널
   에서 경계 차이는 수 mm 로 추정된다 [추정 — 실제 패널 곡률로 계산해 확인할 것].
   트림 여유가 그보다 크면 소성 모델이 재단선을 바꾸지 못한다.

소성이 바꾸는 것은 블랭크가 아니라 **판정**(두께 감소, 성형한계 여유)이다. 그건 v2 다.

**중요**: ARAP 은 "기하적" 방법이 아니라 이미 FEM 이다. 삼각형마다 상수변형률요소(CST)
를 놓고 회전분리 탄성 에너지를 최소화한다. 갈림길은 FEM 이냐 아니냐가 아니라 **구성
모델을 어디까지 진짜로 쓰느냐**였고, v1 은 첫 칸에서 멈춘다.

## 3. 성공 기준

세 가지를 주장한다. 전부 실물 없이 참/거짓이 갈린다.

1. **과소재단이 아니다** — 경계 적합이 바깥으로만 편향되고(§8) 여유가 더해지므로,
   재단선이 평탄화 결과 경계를 침범하지 않는다.
2. **주름 위험을 드러낸다** — 평탄화가 늘린 자리(σ > 1)는 성형 때 압축된다.
3. **찢어짐 위험을 드러낸다** — 성형 변형률 `1/σ − 1` 이 균일연신률을 넘는 자리.

**"블랭크 치수가 정확하다"고 쓰지 않는다.** 확인할 수단이 없다(§11).

### 3.1 부호를 못박아 둔다

야코비안 J 의 특이값을 `σ = (평면 길이) / (3D 길이)` 로 정의한다.

| | 평탄화에서 | **성형에서** | 뜻 |
|---|---|---|---|
| `σ < 1` | 줄어듦 | **늘어남** (변형률 `1/σ − 1`) | 정상. 연신 한계까지 허용 |
| `σ > 1` | 늘어남 | **압축됨** | **주름 위험** |

부호를 헷갈리면 벌점의 방향이 뒤집히고, 결과는 여전히 그럴듯해 보인다. 이 표가
`metrics.py` 와 `energy.py` 의 기준이다.

### 3.2 정정 — "평탄화 면적 ≥ 3D 면적"은 기준이 아니었다

초기 검토에서 "ARAP 결과 면적이 3D 이상이면 과소재단이 아니다"라고 썼는데 **두 겹으로
틀렸다.**

1. ARAP 은 `‖J−R‖²` 을 최소화할 뿐 **면적 하한을 보장하지 않는다.**
2. 애초에 그게 기준이 아니다. **인장 성형에서는 평탄화 면적이 3D 보다 작은 것이
   정상이다** — 블랭크가 작고, 성형이 늘려서 3D 가 된다. 면적이 3D 이상이라면 오히려
   전면적으로 압축(주름)이 일어난다는 뜻이다.

과소재단 보증은 면적 비교가 아니라 **경계 처리**(§8)가 세운다.

**남는 진짜 위험**: 실제 공정이 모델보다 **덜** 늘어나면(마찰 구속, 플랜지에서 재료가
흘러들어옴) 필요한 블랭크가 더 커진다. 이건 계측 없이 한계를 못 정한다 → §11.

## 4. 구조

```
unfold/
├── src/
│   ├── topology.py    반엣지·인접·경계추출·연결성 검사              (순수)
│   ├── element.py     삼각형 국소좌표계, 면적, cotangent 가중        (순수)
│   ├── material.py    MaterialProps + 검증 + 등급 기록              (순수)
│   ├── energy.py      구성모델 인터페이스 + ARAP  ★v2 교체 지점     (순수)
│   ├── initial.py     최적평면 투영 → 뒤집힘 검사 → Tutte 폴백      (순수)
│   ├── solver.py      local-global 반복 + CG (numpy 있으면 가속)     (순수)
│   ├── flatten.py     facade: (verts, faces, props) → FlattenResult (순수)
│   ├── metrics.py     요소별 σ·면적비·주름 위험·연신 한계 판정      (순수)
│   ├── blank.py       경계 추출 → 바깥편향 적합 → 오프셋            (순수)
│   ├── report.py      사람이 읽는 요약                              (순수)
│   └── rhino_io.py    Brep ↔ 메쉬, 결과 → Curve/Mesh          (Rhino 의존)
├── tests/
├── tools/
└── docs/
```

**Rhino 의존을 `rhino_io.py` 한 파일로 몰았다.** 코어는 정점·면 배열만 받는다. 그래서
전개 알고리즘 전체가 Rhino 없이 pytest 로 돌고, `.gha` (C#) 포팅 시 옮길 대상이 명확
하다(플랫폼 원칙 §2.1 그대로).

`energy.py` 가 v2 에서 소성 모델이 들어올 자리다. `solver.py` 는 "요소별 에너지와 그
미분을 주면 푼다"만 알고 어떤 재료인지 모른다.

```
Brep ──rhino_io.mesh_from_brep──> (verts3d, faces)
                                        │
              topology: 다중 껍질·구멍·비다양체 검사 ──실패──> 중단, 이유 반환

              solver + energy(ARAP + 주름벌점) ←── MaterialProps

                                        ▼
              blank: ① 경계 추출 → ② 바깥편향 적합 → ③ 오프셋 → 자기교차 검사
```

**중단 지점을 앞에 둔 이유**: 트림된 Brep 을 메쉬화하면 구멍·중복정점·비다양체 엣지가
흔히 나온다. 통과시키면 솔버가 발산하는 대신 **그럴듯한 틀린 답**을 낸다. 위상 검사에
걸리면 결과를 내지 않고 이유를 돌려준다.

미판정을 통과로 치지 않는다 — `adaptive_mold` 의 규율을 그대로 적용한다.

## 6. 알고리즘

### 6.1 초기 배치

```
최적평면 투영 → 부호면적 검사 → 뒤집힘 있으면 Tutte 매립
```

얕은 외장 패널은 최적평면 투영으로 끝난다(뒤집힘 0). 반구처럼 깊으면 접히는데, 그때만
Tutte 로 내려간다 — 원판 위상 + 볼록 경계면 단사가 보장된다. 심하게 왜곡되지만 ARAP 이
회복시킨다.

### 6.2 ARAP local-global

```
사전계산 (3D 원본에서 한 번):  요소별 국소좌표 + cotangent 가중
반복 {
  local :  요소마다 2×2 야코비안 J → 최적 회전 R   (2×2 SVD 는 닫힌 형식, 라이브러리 불필요)
  global:  가중 라플라시안 L·x = b                  (x, y 를 같은 L 로 따로 푼다)
}
수렴: 상대 에너지 변화 < 1e-6 또는 iters 도달. 실제 반복 수를 info 에 적는다.
```

### 6.3 주름 벌점 — 형상을 바꾸는 유일한 물성

J 의 특이값 `σ₁ ≥ σ₂` 에 대해 ARAP 에너지는 `(σ₁−1)² + (σ₂−1)²` 로, 늘어남과 줄어듦을
**대칭으로** 벌한다. 하지만 판재는 대칭이 아니다 — 성형 중 인장은 소성으로 받아내지만
압축은 압축되는 대신 **주름진다.**

§3.1 의 부호대로, 성형에서 압축이 일어나는 자리는 **평탄화에서 `σ > 1` 인 자리**다.
그래서 `σ > 1` 쪽을 더 강하게 벌해 해를 "성형 시 인장만" 쪽으로 민다.

> 이름 주의: 물리적으로는 *주름* 을 억제하는 것이므로 `wrinkle_penalty` 라 부른다.
> "압축 벌점"이라 부르면 평탄화의 압축(`σ < 1`, 정상인 쪽)을 벌하는 것으로 읽혀
> 부호가 뒤집힌다. 실제로 설계 중 한 번 뒤집혔다.

구현은 **반복 재가중(IRLS)**: 직전 반복에서 `σ₁ > 1` 이었던 요소의 가중치에
`wrinkle_penalty` (k ≥ 1) 를 곱한다. 같은 local-global 뼈대를 쓰고 코드가 거의 안 는다.

**대가**: 가중치가 매 반복 바뀌므로 강성행렬 `L` 을 사전 분해할 수 없다. 그래서 솔버를
Cholesky 가 아니라 **CG** 로 잡는다(§6.5). 두 결정이 서로를 지지한다.

**정직하게 적어 둘 것**: 에너지 단조 감소는 순수 ARAP(`k = 1`)에서만 증명된다. `k > 1`
의 IRLS 에 대해서는 **증명하지 않았다.** 따라서

- 단조성 테스트는 `k = 1` 에서만 단언한다
- `k > 1` 에서는 발산하지 않음만 확인하고 에너지 이력을 `info` 에 남긴다
- **기본값은 `wrinkle_penalty = 1.0`** — 기본 경로가 증명된 경로다. 올리는 것은 명시적 선택.

### 6.4 게이지 고정

ARAP 해는 평행이동·회전만큼 자유도가 남는다. 정점 하나를 고정해 풀고, **마지막에 결과를
주축이 수평이 되도록 강체 정렬**한다.

이게 없으면 같은 입력이 매번 다른 방향으로 나와 회귀 픽스처가 성립하지 않는다.

### 6.5 선형 솔버 — numpy 는 필수가 아니라 가속기

**실측 (2026-08-14, 이 PC)**

| 환경 | numpy |
|---|---|
| Rhino 8 py39 (`~/.rhinocode/py39-rh8/Lib/site-packages`) | **없음** — certifi, packaging, pip, setuptools, wheel 뿐 |
| Rhino 8 py39 + `# r: numpy` 선언 | **numpy 2.0.2** — `~/.rhinocode/py39-rh8/site-envs/default-*/` [실측 2026-08-14] |
| 시스템 Python (테스트용) | numpy 2.2.6 / scipy 1.16.0 |

**[정정 2026-08-14] 위 첫 줄만 보고 "Rhino 에는 numpy 가 없다"로 읽으면 안 된다.**
없는 게 아니라 **선언하지 않으면 안 보이는 것**이다. 스크립트 첫머리에 `# r: numpy`
한 줄을 적으면 Rhino 가 자기 site-env 를 `sys.path` 에 얹는다. 그 한 줄의 값이
20.6배다(아래 표).

**여전히 의존성으로 만들지는 않는다.** 선언은 하되, numpy 가 없는 환경에서도 순수
경로로 계산은 되고 `info` 에 "numpy 없음"이 찍힌다. 정본은 순수 파이썬이고 두 경로가
같은 답을 낸다는 것은 테스트가 지킨다.

`L` 은 대칭 준정부호이고 행당 비영요소가 ~7 개뿐이라 **켤레기울기(CG)** 로 풀린다.
ARAP 반복 사이에 `b` 가 조금씩만 바뀌므로 **직전 해에서 warm start** 하면 수십 회에
수렴한다.

**[실측 2026-08-14로 갱신]** 조건이 추정 때와 다르므로 조건을 함께 적는다 —
`panel_dome` 1600×1600(라이즈 306), Rhino 8.33 py39, 야코비 전처리 + warm start,
에너지 상대변화 1e-6 에서 수렴(6~7회). 값은 `pl.run()` 전체가 아니라 전개 한 판
전체(메쉬화~재단선)다.

| 경로 | 요소 | 정점 | 총시간 |
|---|---|---|---|
| 순수 파이썬 CG | 60 mm | 2,049 | **10.28 s** |
| numpy 사용 | 60 mm | 2,049 | **0.50 s** |
| numpy 사용 | 40 mm | 5,889 | 1.44 s |
| numpy 사용 | 25 mm | 16,385 | 6.14 s |

추정(순수 5초 / numpy 0.2초, ~1,400정점)보다 **둘 다 느렸다.** 정점 수가 1.5배인
것을 감안해도 순수 경로는 추정의 1.4배쯤이다. 그 차이가 "UI 스레드가 10초 멈춘다"로
나타났고, 그래서 numpy 선언·전처리·시간 예산 상한이 들어갔다(J-014).

`solver.py` 가 numpy 를 찾으면 쓰고 없으면 순수 경로로 간다. **두 경로가 같은 답을
내는지는 테스트가 지킨다**(§10.3).

값어치: Rhino 에서 `# r: numpy` 가 되든 안 되든 컴포넌트가 동작한다. 그 검증이 개발을
막지 않는다.

## 7. 물성 (`material.py`)

ARAP 에너지에는 **탄성계수도 푸아송비도 들어가지 않는다.** `E` 를 곱해도 최소점이
그대로라 형상이 안 바뀐다. 그런 항목을 물성 입력에 섞으면 **돌려도 아무 일이 안 일어나는
가짜 손잡이**가 생긴다. 사용자는 조정하고 있다고 믿는데 실제로는 아무것도 안 한다.

그래서 필드마다 등급을 붙이고, `info` 에 **실제로 작동한 물성만** 찍는다("두께 3mm 를
받았고 형상에는 영향 없음"처럼 명시).

| 필드 | v1 에서 하는 일 | 등급 |
|---|---|---|
| `wrinkle_penalty` | `σ > 1`(성형 시 압축) 쪽을 강하게 벌해 해를 인장 쪽으로 민다 | **형상을 바꿈** |
| `elong_max` | 균일연신률. 성형 변형률 `1/σ − 1` 이 넘는 요소를 경고 | 판정만 |
| `thickness` | 막 모델에선 에너지의 전체 배율 → 형상 불변. 중량·재료비용 | 기록만 |
| `name`, `source` | 무슨 재료이고 숫자가 어디서 왔는가 | 기록만 |
| `E`, `ν`, 항복곡선, FLD, r 값 | v2 소성 모델 자리. v1 에서는 **필드도 만들지 않는다** | v2 |

### 7.1 이방성은 넣지 않는다

압연방향을 공정에서 통제하지 않는다. 통제하지 않는 방향에 대해 이방비를 받으면 **근거
없는 숫자가 형상을 바꾼다.** 없느니만 못하다.

**뒤집을 조건**: 재단 시 압연방향을 지정하고 성형까지 그 방향이 유지되는 공정이 되면
`energy.py` 에 방향 가중을 추가한다.

### 7.2 프리셋을 비워 둔다

알루미늄 5052 의 균일연신률을 지금 출처와 함께 댈 수 없다. 근거 없는 숫자를 기본값으로
넣으면 아무도 안 고치고 그대로 쓴다.

`source` 를 필수 필드로 두고, 값을 넣는 사람이 어디서 왔는지 적게 한다. 비어 있으면
`warn` 에 "출처 미기재"를 남긴다.

## 8. 경계 다듬기 (`blank.py`)

```
① 추출   평면 메쉬 경계 → 폴리라인 + 특징점(꺾임각 임계 초과) 표시
② 적합   특징점 사이 구간마다 곡선 적합.  ★바깥쪽으로만 편향
③ 오프셋 여유 적용 → 자기교차 검사
```

**②의 바깥 편향이 핵심.** 삼각망 경계는 톱니처럼 거칠어서 그냥 적합하면 곡선이 폴리라인
안팎을 넘나든다. **안쪽으로 넘어간 구간이 곧 과소재단이다.** 적합 오차를 한쪽으로만
허용해 곡선이 항상 폴리라인 바깥에 있게 한다. 재료를 조금 더 쓰는 대신 §3 의 보증이
유지된다.

**특징점을 고정하는 이유**: 패널 모서리다. 평활화가 코너를 둥글게 뭉개면 재단물이 원래
패널이 아니게 된다.

### 8.1 알려진 한계 — 자기교차

오목한 모서리에서 오프셋이 자기교차할 수 있다. **v1 은 고치지 않고 검출해서 경고한다.**
외장 패널은 대개 볼록 사각형이라 실제로 걸릴 일이 드물고, 견고한 오프셋을 처음부터
만드는 건 이 프로젝트의 본론이 아니다.

**뒤집을 조건**: 실제 패널에서 걸리면 RhinoCommon `Curve.Offset` 으로 우회한다(대신
그 경로는 Rhino 밖에서 테스트되지 않는다).

## 10. 검증 전략

전개 결과는 **그럴듯해 보이는 것과 맞는 것을 눈으로 구별할 수 없다.** 그래서 답을 아는
케이스와 불변량으로 조인다.

### 10.1 이론해 — 답을 아는 네 가지

| 케이스 | 알고 있는 답 | 통과 조건 |
|---|---|---|
| 평면 | 항등 | σ = 1, 형상 일치 (수치오차 이내) |
| 원기둥 조각 (반경 R, 각 β, 높이 h) | 전개 가능 → 직사각형 | max\|σ−1\| ≈ 0, 폭 = Rβ, 높이 = h |
| 원뿔 조각 (반각 α, 모선 L) | 전개 가능 → 부채꼴 | max\|σ−1\| ≈ 0, 반경 = L, 각 = 2π sin α |
| 구면 캡 (반경 R, 반각 θ) | **전개 불가** — 두 극단이 닫힌 형식 | `R·sinθ ≤ 외곽반경 ≤ R·θ`, 축대칭 |

구면 캡이 핵심이다. 축대칭 전개를 `r(φ)` 로 두면 (φ 는 극에서의 각)

```
σ_r    = r'(φ) / R          반경방향
σ_hoop = r(φ) / (R·sinφ)    원주방향
```

ARAP 에너지의 두 항을 **각각** 0 으로 만드는 사상이 극단이고, 둘 다 닫힌 형식이다:

| 극단 | 조건 | 사상 | 외곽 반경 |
|---|---|---|---|
| 정사영 | `σ_hoop = 1` | `r = R·sinφ` | **`R·sinθ`** |
| 등거리 | `σ_r = 1` | `r = R·φ` | **`R·θ`** |

각 극단은 한 항을 0 으로 만들고 다른 항을 양수로 남기므로 최소점은 **그 사이**에 있다.
따라서 `R·sinθ ≤ 결과 ≤ R·θ` 여야 한다. 벗어나면 구현이 틀린 것이다.

### 10.1.1 정정 — 등면적 반경은 하한이 아니다

초안은 하한을 등면적 반경 `2R·sin(θ/2)` 로 썼는데 **틀렸다.** 등면적 사상은 위 두
극단과 무관한 **제3의 사상**이고 ARAP 은 등면적법이 아니므로, 그것을 넘겨야 할 이유가
없다. 세 값의 순서는 `R·sinθ < 2R·sin(θ/2) < R·θ` 이고, ARAP 은 실제로 등면적 반경보다
**조금 아래**로 떨어지며 그 차이가 곡률과 함께 커진다
[실측 2026-08-14, R=500, nr=8 nt=24, iters=200]:

| θ | `R·sinθ` | 등면적 | `R·θ` | ARAP |
|---|---|---|---|---|
| 0.3 | 147.76 | 149.44 | 150.00 | 149.449 |
| 0.6 | 282.32 | 295.52 | 300.00 | 295.498 |
| 0.9 | 391.66 | 434.97 | 450.00 | 434.261 |
| 1.2 | 466.02 | 564.64 | 600.00 | 560.858 |

**구간과 픽스처는 역할이 다르다.** 구간은 유도된 주장이라 느슨하고(θ=0.6 에서 폭 6.3%)
부호 오류·전치처럼 크게 어긋나는 결함을 잡는다. 좁은 회귀 방어는 골든 픽스처가
실측값을 상대오차 1e-6 으로 고정해 맡는다(§10.3).

구면 캡은 **주름 경고의 동작 확인**도 겸한다. 볼록 돔은 평탄화에서 원주방향이 반드시
늘어나므로(`σ_hoop > 1`) §3.1 대로 성형 시 압축 = 주름 위험이 뜬다. 경고가 **안 뜨면**
판정 쪽이 틀린 것이다.

### 10.2 불변량 — 답을 몰라도 검사되는 것

| # | 불변량 | 잡는 실수 |
|---|---|---|
| 1 | 강체 불변 — 입력을 회전·평행이동해도 (강체 정렬 후) 같은 결과 | 좌표계 혼동 |
| 2 | 축척 공변 — 입력 s 배 → 블랭크 s 배, σ 는 불변 | 단위·정규화 |
| 3 | 순서 무관 — 정점·면 순서를 섞어도 같은 답 | 인덱스 오류 |
| 4 | 에너지 단조 감소 (`wrinkle_penalty = 1.0` 에서만) | local/global 단계 |
| 5 | 뒤집힘 0 (얕은 케이스) | 초기 배치 |
| 6 | 세분화 수렴 — 요소 크기 절반 → 변화량이 줄어들 것 | 이산화 |

1·3 이 특히 값어치가 크다. 구현 실수의 대부분이 여기서 걸린다.

### 10.3 두 솔버 경로 대조

numpy 경로와 순수 파이썬 경로가 **같은 골든 픽스처를 통과해야 한다.** 시스템 파이썬에
numpy 가 있으므로 양쪽을 다 돌릴 수 있다. 픽스처는 `adaptive_mold` 와 같은 방식으로 둔다.

### 10.4 Rhino 실측

실제 패널 곡면 한 장으로 `blank` 곡선이 나오고, 그 면적이 3D 곡면 면적 이상일 것.
`.gh` 저장·재시작 후 툴팁이 살아 있을 것.

## 11. 검증할 수 없는 것 — 처음부터 적어 둔다

- **실제로 성형했을 때 이 블랭크가 맞는지.** 실물도 계측도 없다. 산출물에 "블랭크
  치수가 정확하다"고 쓰지 않는다.
- **실제 공정이 모델보다 덜 늘어나는 경우**(마찰 구속, 플랜지에서 재료 유입). 그러면
  필요한 블랭크가 더 커진다. 여유로 덮이는지는 계측 전에는 알 수 없다(§3.2).
- **`wrinkle_penalty > 1` 의 수렴성.** 증명하지 않았다(§6.3).
- **주름이 실제로 생기는지.** `σ > 1` 은 주름 *위험* 이지 발생 예측이 아니다. 실제
  주름은 좌굴 해석의 영역이고 두께·구속·경로에 달렸다.
- **두께 감소·성형한계·스프링백.** v2 소성 모델과 함께 온다.
- **§2.4 의 "경계 차이 수 mm" 추정.** 실제 패널 곡률로 계산해 확인해야 한다.
