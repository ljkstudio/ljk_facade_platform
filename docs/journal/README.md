# 개발 저널 — 기록 규약

이 폴더의 기록은 **읽히기 위한 것이 아니라 다음 개발을 자동 생성하기 위한 재료**입니다. 그래서 형식이 고정돼 있습니다.

---

## 1. 왜 이 형식인가

**"무엇을 했다"는 자동화에 쓸모가 없습니다.** 쓸모 있는 단위는 **"어떤 상황에서 무엇을 골랐고, 안 그랬으면 어떻게 깨지는가"** 입니다. 전자는 일기, 후자는 규칙입니다.

특히 **기각한 대안**과 **재발 조건**이 빠지면 자동 생성이 성립하지 않습니다. 근거 없는 결론만 남으면 다음번에 상황이 달라졌을 때 그대로 적용해도 되는지 판단할 수 없고, 결국 사람이 처음부터 다시 생각하게 됩니다.

---

## 2. 기록 네 종류

| 종류 | 담는 것 | 자동 생성에서의 역할 |
|---|---|---|
| **TRAP** (함정) | 증상 → 원인 → 해결 → **재발 조건** | 가장 값어치 높음. 다음 코드가 같은 데 안 빠짐 |
| **DECISION** (결정) | 선택 + 근거 + **기각한 대안** + 뒤집을 조건 | 생성기가 기본값을 고를 근거 |
| **FACT** (실측) | 버전·경로·수치. **추측과 명확히 구별** | 환경 가정을 검증 가능하게 |
| **PROCEDURE** (절차) | **손으로 두 번 이상 한 것** | 그대로 스크립트·템플릿이 됨 |

네 종류에 안 들어가면 적지 않습니다. 분류가 애매하면 그건 대개 기록할 가치가 없는 것입니다.

### 적지 않는 것

- 코드를 읽으면 알 수 있는 것 (구조, 함수 목록)
- git 히스토리가 이미 담고 있는 것 (무엇을 언제 바꿨는지)
- 이 프로젝트에서만 의미 있는 일회성 사건
- **아직 확인 안 된 추측** — 적으려면 `미검증`으로 명시

---

## 3. 언제 쓰는가

**각 마일스톤이 끝나는 즉시.** 사후 정리로는 못 만듭니다 — 결론은 코드에 남지만 **기각한 대안은 아무 데도 안 남고**, 세션이 끝나면 왜 그렇게 했는지가 사라집니다.

[`20_gha_csharp_port.md`](../../20_gha_csharp_port.md) §5의 M0~M3 각 단계 완료 시점이 기록 시점입니다.

---

## 4. 파일 이름

```
J-001-M0-toolchain.md
J-002-M1-golden-fixtures.md
```

`J-<순번>-<마일스톤>-<주제>.md`. 순번은 프로젝트 안에서만 유일하면 됩니다.

작성은 [`TEMPLATE.md`](TEMPLATE.md)를 복사해서 시작합니다.

---

## 5. 스킬로 승격하는 기준

저널은 프로젝트 맥락이 있어야 읽히고, 스킬은 **맥락 없이도 통해야** 합니다. 성격이 다르므로 자동으로 올리지 않습니다.

> **저장소 3개에서 반복되면 스킬로 승격한다.**

이 기준이 있어야 일회성 사건이 규칙으로 굳는 걸 막습니다. 한 번 겪은 것은 그 프로젝트의 사정일 수 있지만, 세 번 겪은 것은 Rhino 플러그인 개발 자체의 성질입니다.

승격 대상 저장소 후보: `ljk_facade_platform`, `howick-grasshopper`, `catia-tree`, `2D-DXF-Parser`, `sketch2cad`, `rhino_viewer`

승격 시 목적지:

```
~/.claude/skills/rhino-plugin/
├── SKILL.md        ← TRAP·DECISION을 규칙으로
└── templates/      ← PROCEDURE를 스캐폴딩으로
```

**스킬은 저널이 쌓이기 전에 만들지 않습니다.** 겪지 않은 것을 추측으로 채우면 이 방식이 피하려던 바로 그 문제가 생깁니다.

---

## 6. 기존 도구와의 관계

이 저장소는 아직 GSD(`.planning/`)를 쓰지 않습니다. 저널이 쌓인 뒤 다음 도구로 넘길 수 있습니다.

| 도구 | 쓰임 |
|---|---|
| `learn` | 프로젝트 학습 관리 |
| `gsd-extract-learnings` | 완료 산출물에서 결정·교훈·패턴 추출 |
| `skillify` | 검증된 흐름을 영구 스킬로 코드화 |
| `graphify` | 저널을 지식 그래프로 질의 |

**새 체계를 만드는 것이 아니라 이 도구들이 먹을 재료를 정확한 형식으로 쌓는 것**이 이 폴더의 목적입니다.
