# J-007 · 실물 로봇 형상 매핑 — 스틱 피겨에서 IRB 6700 으로

> 웹 시뮬레이터의 GLB 9개(BASE, LINK01~06, CYLINDER, ROD)를 Rhino 로 들여와
> 관절 프레임에 얹었다. 매핑 자체는 한 줄이고 — 파트가 영각 자세로 제자리에
> 있으므로 `joint_frames(pose)[j] * Translation(-pivot_j)` 이 전부다 —
> **일이 된 곳은 좌표계 판정과 검증이다.**
> 프레임 비용은 0.29 → 0.55 ms 로 거의 늘지 않았다(12만 면).

---

## FACT-01 매핑은 한 줄이다 — 파트가 영각 자세로 제자리에 있기 때문 ★★

원본 `merge_glb.py` 주석: *"각 파트는 이미 공통 좌표계(Z-up, meter)로 제자리에
있으므로 변환 없이 합치고"*. 그래서 임포트한 그대로가 **영각(零角) 자세**다.

    M_j(pose) = joint_frames(pose)[j] * Translation(-pivot_j)

- 영각에서 `joint_frames` 는 `Translation(pivot_j)` 이므로 **M_j(0) = 항등**이다.
  이것이 정합의 증거이고 `test_zero_pose_is_identity` 가 확인한다.
- **`robot.py` 의 피벗이 이 GLB 실측에서 나온 값이었다** — 그래서 둘이 맞는다.
  J6 피벗 `x=1.876 m` ↔ link6 바운딩박스 `x 1875.8~1912.5 mm`.
  원본 KINEMATICS.md 가 "URDF 값과 GLB 실측이 다르면 GLB 우선"이라고 적어 둔
  결정이 여기서 배당을 냈다.

## FACT-02 좌표계는 판정했고, 하드코딩하지 않았다 ★★

**증상:** 임포트하면 X 는 맞는데(link6 x=1875.8) Z 가 이상하다 —
`base z[-360,360]`, `link5 z[-92,91]`. 기대값은 `base z 0~370`,
`link5 z 2000~2190`.

**원인:** glTF 는 Y-up 규약이다. 원본이 이미 Z-up 인데 Rhino 임포터가
Y-up→Z-up 변환을 **한 번 더** 걸어 원래 Z 가 −Y 로 갔다.

**해결:** X축 −90° 회전. 다만 **하드코딩하지 않고 채점해서 고른다** —
`robot.py` 의 J6 피벗이 link6 바운딩박스 안에 들어가는 후보를 뽑는다.
근거: link6 은 툴 플랜지이므로 J6 회전 피벗이 그 안에 있어야 한다.

| 후보 | J6 피벗까지 거리 | 전 파트 최소 z |
|---|---|---|
| 그대로 | 2,835.5 mm | −456.0 |
| **X −90** | **0.0 mm** | **−0.0** |
| X +90 | 4,110.0 mm | −2,276.1 |

판정이 3자리 수로 갈린다. 원본이 다시 내보내지면서 규약이 바뀌어도 도구가 알아서 맞춘다.

**대조 (KINEMATICS.md 의 world z 범위, mm):**

| 파트 | 실측 z | 기대 z | 차이 |
|---|---|---|---|
| base | 0.0 ~ 373.5 | 0 ~ 370 | 0 / 3 |
| link1 | 215.0 ~ 1015.5 | 220 ~ 1020 | 5 / 5 |
| link2 | 594.7 ~ 2062.6 | 590 ~ 2060 | 5 / 3 |
| link3 | 1730.7 ~ 2276.1 | 1730 ~ 2280 | 1 / 4 |
| link4 | 1973.0 ~ 2237.0 | 1970 ~ 2240 | 3 / 3 |
| link5 | 2003.6 ~ 2189.0 | 2000 ~ 2190 | 4 / 1 |
| link6 | 2005.0 ~ 2205.0 | 2010 ~ 2200 | 5 / 5 |

**최대 5 mm** — 원본 문서가 "근사"로 적어 둔 범위 안이다. 3.2 m 로봇에서 5 mm 는
표시 목적에 충분하고, 기구학은 GLB 가 아니라 `robot.py` 의 피벗이 정본이다.

**단위 판정에 Z 를 쓰면 안 된다.** 첫 판에서 `base z 상한 = 360` 을 보고
"이미 mm"라고 맞는 결론을 냈지만 **근거가 틀렸다**(그 360 은 실제로는 y 성분).
전 파트의 최대 절대좌표(2,276)로 판정하도록 고쳤다 — 축과 무관한 근거다.

## TRAP-01 임포트와 정리 사이에서 예외가 나면 문서가 오염된다 ★★

- **증상:** `test_panels.3dm` 에 **메시 4,592개**가 남았다(정상 5개 → 4,597개).
  전부 현재 레이어(`panel_flat`)에 원본 Brep 과 섞여 들어갔다.
- **원인:** 정리 코드가 `try` 안에 있었고 저장 직전에 예외가 났다
  (`File3dmLayerTable.Add()` 는 `void` 라 인덱스를 돌려주지 않는다 —
  `att.LayerIndex = None` 으로 `TypeError`).
- **해결:** 정리를 **`finally` 로 옮겼다.** 열려 있는 문서를 건드리는 도구는
  예외 경로에서도 원복되어야 한다.
- **복구:** 원본이 Brep 5개뿐이고 Mesh 는 0개였으므로 "메시만 지운다"가
  "임포트한 것만 지운다"와 같았다. **지운 뒤 객체 수가 5인지 확인**하고 끝냈다.
- **재발 조건:** 임포트·생성으로 문서를 건드리는 도구를 쓸 때마다.
- **일반화:** 대상 선별은 **이름·레이어가 아니라 id 차집합**으로 한다.
  이름으로 고르면 사용자 객체를 지운다.

## FACT-03 실물 형상은 사실상 공짜다 — 메시를 옮기지 않기 때문 ★★

`PostDrawObjects` 안에서 파트마다 `PushModelTransform(xf)` → `DrawMeshShaded` →
`PopModelTransform()`. **메시는 원본 그대로 그린다.**

| | 프레임당 그리기 | fps |
|---|---|---|
| 선·폴리라인만 | 0.17~0.76 ms | 21.2 |
| **+ 실물 12만 면** | **0.41~0.98 ms** | **21.6~21.8** |

- 프레임마다 `posed_meshes()` 로 복제하면 12만 면을 매번 만든다 — 그래서 복제는
  정지 상태(출력)에만 쓴다. 같은 결과를 두 경로로 내되 비용이 다른 구조다.
- 표시용으로 원본 249,339면 → **119,988면**(48.1%)으로 줄였다.
  `Mesh.Reduce`. 원본 밀도가 필요한 작업(간섭 검사 등)이면 다시 만들어야 한다.
- **스틱 피겨와 겹쳐 그리지 않는다** — 선이 몸체 안쪽에 비쳐 지저분하다.
  실물이 없거나 `show_body=False` 일 때만 선으로 그린다.

## FACT-04 두 표시 경로가 같은 자세인지 대조했다 ★

`link_lines_mm` 은 미터 좌표를 1000배 한 뒤 base_plane 을 걸고,
`part_transforms` 는 변환을 켤레변환(S·M·S⁻¹)한 뒤 base_plane 을 건다.
**경로가 다르므로 한쪽만 고치면 조용히 어긋난다** — 화면으로는 로봇이 그럴듯하게
서 있고 계산된 위치와 다른 곳에 그려진다(J-006 TRAP-03 과 같은 종류).

`test_agrees_with_link_lines` 가 **기울고 옮겨진 베이스**로 두 경로를 대조한다
(축이 정렬된 평면은 규약 실수를 숨긴다). 6관절 전부 **1e-6 mm 이내 일치.**

## 미해결

- **밸런서(cylinder / rod)는 근사다.** 실린더와 로드를 같은 프레임에 묶어 J2 의
  −0.25 배만 돌린다. 그래서 **피스톤이 늘어나지 않는다**(원본 문서의
  `piston_joint: prismatic 0.15` 미구현). 따로 움직이면 둘이 어긋나 보이므로
  어긋나는 것보다 안 늘어나는 것을 골랐다. 실물 대조 안 됨 — **미검증**.
- 툴(롤러) 형상이 없다. TOOL_LENGTH 0.34 m 지점에 원만 그린다.
  실제 롤러·홀더 모델이 있으면 J6 프레임에 같은 방식으로 붙일 수 있다.
- 간섭 검사 없음. 실물이 있으므로 이제 가능하다 — 표시용으로 48% 줄인 메시라
  판정에 쓰려면 밀도를 다시 봐야 한다.
- `irb6700_parts.3dm`(4.18 MB)은 웹 저장소의 GLB 에서 파생된 산출물이다.
  재생성에는 `ljks_website_v2` 가 형제 경로에 있어야 한다 — 그래서 저장소에
  넣었다. 원본이 바뀌면 `import_robot_glb.py` 를 다시 돌린다.
